## P1 + P2 — `spec(D¹) = -spec(D⁰)` и градуировка (`rebuild_c43_grading.py`)

- **P1 подтверждено аналитически и численно**, причём это свойство САМОЙ формулы
  `D^t(n,σ)=σ(n+3/2)+(t-1/2)·3` (сдвиг индекса), не зависит от выбора функции
  кратности `m(n)` — проверено на стандартной `m(n)=(n+1)(n+2)` И на произвольной
  «странной» функции: совпадает в обоих случаях.
- **P2 подтверждено**: одиночный `D⁰` не проходит критерий градуировки
  (`λ=1` есть, `λ=-1` отсутствует — явный no-go, ровно как заявлено), а
  `D⁰⊕D¹` проходит его точно на каждом уровне (собранный мультисет полностью
  симметричен относительно `x→-x`).

## P5 — `T↔1-T` (`rebuild_c43_grading.py`)

Общий результат (не был очевиден из прозы): унитарная эквивалентность `T` и `1-T`
для проектора ранга `r` на `C^d` держится **ровно** когда `r=d-r` («сбалансированный»
проектор). Пример из прозы (ранг-1 проектор на `C²`) — частный случай этого общего
факта, а не что-то специфичное для него самого. Практический вывод: прежде чем
считать `T↔1-T` содержательным открытием, нужно проверить, какую именно `(d,r)`
вынуждает реальная SU(3)/generation-структура.

## P4 / OB10 — ловушка сигнатуры `Cl(9,0)` vs `Cl(6,3)` (`rebuild_ob10_clifford.py`)

Позитивные контроли (`Cl(0,3)→-1`, `Cl(2,0)→+1`) прошли точно как и ожидалось —
метод решения (интерwiner `B` как нуль-пространство линейной системы, а не
взятая из таблицы формула) доверенный.

Для нечётной полной размерности `n=9` обнаружилась более острая версия ловушки,
чем в прозе: интерwiner `B` существует **только для одного из двух** стандартных
уравнений зарядового сопряжения (`Bγ=+γ*B` или `Bγ=-γ*B`) — никогда для обоих,
никогда ни для одного. И какое именно уравнение работает **зависит от сигнатуры**:

```
наивный "Cl(9,0)" (неверная маркировка)  -> работает ТОЛЬКО +γ* -> BB̄ = +1 (real)
честный Cl(6,3) (реальная сигнатура)     -> работает ТОЛЬКО -γ* -> BB̄ = -1 (quaternionic)
```

**Подтверждает claim прозы буквально** («прямое вычисление B дало BB̄=-I») и
уточняет механизм ловушки: дело не в двусмысленности знака внутри одной
сигнатуры — это выбор ТИПА уравнения зарядового сопряжения, который молча
переключается между сигнатурами. Чтение ответа из таблицы mod 8 для «9,0»
даёт не просто неточный, а **противоположный** тип реальности.

## P3 / OB11(i) — SU(3)-содержание `8v` (`rebuild_ob11_triality.py`)

Полностью реконструировано с нуля из структурных констант октонионов
(Cayley-Dickson от кватернионов — без запоминаемой таблицы Фано):

- `g₂ = Der(O)` вычислена как буквальное нуль-пространство условия деривации —
  **размерность НЕ предполагалась, а получена**: `dim(g₂)=14` (учебное значение).
- `su(3)` = стабилизатор `e₁` внутри `g₂` — тоже вычислена, не предположена:
  `dim(su(3))=8` (учебное значение).
- Разложение весов `Im(O)=C⁷` под общим элементом `su(3)`: один нулевой вес
  (синглет) + шесть ненулевых весов, симметричных относительно смены знака
  (триплет + сопряжённый триплет) — **ровно `1+3+3̄`**.
- ⇒ `8v = 1+1+3+3̄` **подтверждено**.

**Реальный баг найден и исправлен по пути**: первая попытка построить матрицы
`L_i` левого умножения ограничивала их действие на `Im(O)` (7-мерно) — но
`e_i·e_i=-1` попадает в ВЕЩЕСТВЕННОЕ направление, поэтому левое умножение НЕ
замыкается на мнимом подпространстве. Закон альтернативности (уже проверенный
на шаге 1) действительно даёт `L_i²=-I`, но только как оператор на ПОЛНОЙ
8-мерной `O`, не на её сужении. Позитивный контроль (Cl(0,7)) поймал это до
того, как ошибка могла испортить шаг 3 — `g₂`/`su(3)` вычислялись напрямую из
структурных констант и багом не были затронуты (проверено: `Lmat` нигде не
использовался за пределами самого шага 2).

**Обновление (тот же день, `rebuild_ob11_spinor_lift.py`): `8s`/`8c` теперь
тоже построены и подтверждены.** Конструкция сделана поэтапно, с воротами
после каждого шага (позитивный контроль перед следующим шагом), а не
написана целиком до первого запуска — прямое применение процессного урока
выше. Переиспользован уже проверенный код: `su(3)` на `Im(O)` из
`rebuild_ob11_triality.py`, Cl(p,q)-конструкция Йордана-Вигнера из
`rebuild_ob10_clifford.py`.

Пять стадий, каждая со своим позитивным контролем:
1. `su(3)` на `Im(O)`: `dim(g₂)=14`, `dim(su(3))=8` — воспроизведено точно.
2. `Cl(8,0)`: 16×16 `Γ_a`, все `Γ_a²=I`, взаимно антикоммутируют — подтверждено.
3. Оператор хиральности `Γ_chiral=Γ₁···Γ₈`: `16=8s⊕8c` подтверждено (8/8 деление
   собственных значений `±1`).
4. **Новый узел — подъём `so(8)→spin(8)`**, `S(X)=(1/4)Σ X_ab Γ_aΓ_b`,
   **проверен как гомоморфизм алгебр Ли** (`[S(X),S(Y)]=S([X,Y])`) на случайных
   элементах `so(8)` ДО того, как использован для чего-либо ещё — невязка на
   уровне машинной точности (`4·10⁻¹⁵`).
5. Разложение весов внутри каждого сектора хиральности.

**Один пойманный по пути баг проверки (не конструкции)**: первая версия
проверяла, что `S(X)` эрмитова — но `Γ_a` эрмитовы с `Γ_a²=I`, поэтому
`Γ_aΓ_b` для `a≠b` АНТИэрмитова, и `S(X)` для вещественного `X` тоже
антиэрмитова (как и положено генератору унитарного представления) — не
эрмитова. Гомоморфизм Ли из шага 4 уже подтвердил конструкцию с точностью до
машинной погрешности; ошибочным было ожидание в самой проверке, поймано
немедленно, не тихим ослаблением допуска.

**Результат: `8s` и `8c` не просто совпадают по паттерну `1+1+3+3̄` с `8v` —
они несут ТОТ ЖЕ САМЫЙ мультисет весов**, с точностью до 4 знаков:
`[-2.647, -2.319, -0.329, 0, 0, 0.329, 2.319, 2.647]` идентично для всех трёх
каналов при одном и том же случайном элементе `su(3)`.

**OB11(i) теперь подтверждён для ВСЕХ ТРЁХ triality-каналов**, независимо, с
нуля, через явную спинорную конструкцию — claim прозы о совпадении `8v`,
`8s`, `8c` воспроизведён полностью.

## Процессный урок (записан, а не молча пропущен)

`rebuild_ob11_triality.py` был написан целиком (все 5 шагов) до первого
запуска — баг в `L_i` обнаружился только на шаге 2 из-за этого. Пошаговое
исполнение (запустить шаг 1, убедиться, ПОТОМ писать шаг 2) поймало бы то же
самое быстрее и без риска, что похожая ошибка тихо просочилась бы в шаг 3-5
незамеченной. Позитивные контроли на каждом шаге — то, что реально спасло
здесь ситуацию, но incremental execution дешевле, чем полагаться только на
контроли post-hoc.

## Что это НЕ означает

1. Ни одно из этих подтверждений не доказывает, что математика физически
   реализуется природой — только то, что прозаические claims воспроизводимы
   независимым построением (per `claim.md`'s Gate 1/2 non-transfer rule).
2. P3's частичный статус означает: прежде чем main experiment (`A + D_full +
   triality`) опирается на «все три канала эквивалентны», это нужно закрыть
   отдельно — иначе весь OB11(iii)-тест (`triality как 1⊗t`) строится на
   непроверенном фундаменте.
3. Kill-условия K1–K4 из `claim.md`, предрегистрированные до main experiment,
   остаются в силе без изменений — этот раунд их не трогал.
