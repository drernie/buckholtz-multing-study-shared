## The seeded defect

The "independent confirmation" is a tautology, not a discovery. Route 2's
fields are *defined* as `g_route2 = g_R1 * lam` and `phi_route2 = phi_R1
/ lam` — specifically constructed so their product cancels `lam` and
reduces algebraically to `g_R1 * phi_R1`. The code comment even says so:
`# defined this way specifically so the product is invariant`. Running
`sp.simplify(c_route1 - c_route2)` on an expression that is
algebraically zero by construction will, unsurprisingly, return zero.

This is not two independent constructions converging on the same
invariant — it is one construction (Route 1) and a re-parameterization
of it (Route 2) that was *designed* to preserve the product. No new
information was generated by "trying" different values of `lambda`; the
cancellation holds identically for every `lambda` because it's an
algebraic identity, not an empirical coincidence.

## Why this changes the correct answer

The report's conclusion — "strong independent confirmation that Routes 1
and 2 describe the same underlying physics" — is unsupported. A genuine
independent check would require Route 2 to be derived from a
*physically distinct* starting point (a different Lagrangian, a
different symmetry, a different limit) whose relationship to Route 1's
fields is not fixed by definition to preserve the invariant. As written,
the "check" cannot fail — which is itself the signature of a
tautological test (docs/146 Category 2: reused-weakened-result /
post-hoc numerology family — an identity dressed up as a finding).

## What a correct detection should name

- The field redefinition `phi_route2 = phi_R1 / lam` is chosen
  specifically to cancel `g_route2`'s `lam` factor — the invariance is
  definitional, not derived.
- A test that cannot in principle fail (holds for "any value of
  lambda") is not evidence of anything beyond algebra.
- What would make this a real check: deriving `g_route2`/`phi_route2`
  independently (e.g., from a second, physically motivated field
  redefinition not chosen to preserve the product) and *then* checking
  whether the invariant agrees.
